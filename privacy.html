Draft for review before production use

This draft describes the data handling implemented in the current SmartOA prototype. It should be reviewed by the responsible organization before public or clinical deployment.

Information entered into SmartOA

The current prototype can store patient intake details, pain and mobility responses, occupation information, sensor readings, screening results, report timestamps, and the identity of the authorized healthcare worker using the console.

Where data is stored

Screening reports are stored locally in the browser using IndexedDB on the device running SmartOA. The current prototype also keeps a browser copy of the authenticated healthcare worker identity for offline continuity.

Authentication

When the local server is available, healthcare worker login uses a server session cookie. The prototype does not include third-party advertising or analytics code.

Sharing

Reports are intended to remain on the screening device unless a user deliberately exports, downloads, or shares information. The current prototype does not implement a central patient database or automatic cloud upload.

Important review item

Before production use, the responsible organization should define retention periods, access controls, backup procedures, breach response, applicable health-data requirements, and the exact legal entity responsible for processing.
